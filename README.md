# 🌐 AstrBot 局域网 WOL 唤醒插件 (V2.0)

简易、高效的局域网唤醒工具。支持单播/子网广播/全局广播三发机制、多设备管理、一键批量唤醒，以及动态开机状态检测，完美适配慢速启动设备。

## ✨ 特性

- **三发唤醒机制**：底层自动并发发送单播（IP）、子网定向广播（x.x.x.255）、全局广播（255.255.255.255）三种唤醒包，尽最大可能穿透网络隔离。
- **多设备管理**：支持绑定多台设备，自定义设备名称，独立配置端口与广播地址。
- **一键批量唤醒**：自定义“一键唤醒列表”，一条指令同时唤醒多台设备（如 NAS + 台式机），并并发检测上线状态。
- **动态开机检测**：发送唤醒包后自动轮询状态，实时反馈等待进度，支持自定义超时时间。
- **安全隔离**：严格限制仅允许指定白名单用户在私聊中使用，防止群聊滥用。
- **异常可视**：详细的发送日志输出，一旦唤醒失败，可通过日志精准定位是发包失败还是网络拦截。

## 🐳 Docker 部署注意事项（⚠️ 必看）

**强烈推荐将 Docker 网络模式设置为 `host`！** 桥接模式下存在严重的网络隔离问题，极易导致唤醒“时好时坏”。

### 🟢 推荐方案：Host 模式 (即插即用，100% 成功率)

在 `docker-compose.yml` 中添加 `network_mode: host`，或在 `docker run` 命令中添加 `--network=host`。

**为什么推荐？**
容器直接共享宿主机网络，WOL 的广播包和单播包都能无阻碍地直达物理局域网。这是最符合 WOL 协议设计初衷的网络模式，无需任何额外配置即可稳定唤醒。

### 🔴 已知问题：Bridge 桥接模式 (玄学成功率，不推荐)

默认的 Docker 桥接模式会**完全拦截所有广播包**（包括 `255.255.255.255` 和 `x.x.x.255`）。这意味着插件发出的 3 个包中，只有发向设备 IP 的“单播包”能勉强通过 NAT 发出去。

**为什么桥接模式下会“时好时坏”？**
单播包的送达严重依赖宿主机的 ARP 缓存和路由器的 MAC 地址表。当电脑关机较长时间（通常超过 5 分钟）后：
1. 宿主机的 ARP 缓存过期被回收，导致宿主机甚至无法构造出发向目标 IP 的数据包，直接丢弃。
2. 路由器（如 OpenWrt）的 MAC 地址表老化，收到未知单播包时会直接丢弃而非泛洪。

这就导致了“刚关机能唤醒，关久了就不行”的玄学现象。

**🛠️ 如果被强制要求使用桥接模式，必须进行以下补救：**
你需要在宿主机系统上手动添加永久静态 ARP 绑定，并在路由器添加静态 MAC 绑定，确保即使设备下线，网络设备也不会遗忘其 MAC 地址。但这非常繁琐且极易失效，**强烈建议切换至 Host 模式**。

## 📋 指令说明

### 📦 设备管理

- **绑定设备**
  - 多设备模式：`/绑定 <名称> <MAC> <IP> [端口] [广播]`
  - 单设备模式：`/绑定 <MAC> <IP> [端口/广播] [广播]`
  - 示例：
    - `/绑定 台式机 AA:BB:CC:DD:EE:FF 192.168.1.5`
    - `/绑定 NAS AA:BB:CC:DD:EE:FF 192.168.1.6 7 192.168.1.255`
    - `/绑定 AA:BB:CC:DD:EE:FF 192.168.1.5 10.0.0.255` (单设备模式智能识别广播地址)

- **解绑设备**：`/解绑 [名称]`
  - 不填名称会显示可解绑的设备列表。

- **查看设备列表**：`/设备列表`
  - 概览所有已绑定设备的名称、IP 和 MAC。

- **查看设备详情**：`/查看设备 [名称]`
  - 查看某台设备的完整配置（含端口和广播地址）。单设备模式可省略名称。

### 🚀 唤醒操作

- **唤醒设备**：`/开机 [名称]`
  - 发送 WOL 唤醒包，并自动等待检测上线状态（超时时间由配置决定）。单设备模式可省略名称。

- **一键唤醒**：`/一键唤醒`
  - 批量唤醒“一键唤醒列表”中的所有设备，并并发检测上线状态，输出最终报告。

### ⚙️ 一键唤醒列表管理

- `/一键唤醒添加 [名称]` ：将已绑定的设备加入一键列表（支持空格分隔添加多个）
- `/一键唤醒移除 [名称]` ：从一键列表中移除
- `/一键唤醒列表` ：查看当前一键列表
- `/一键唤醒清空` ：清空一键列表

### 💡 其他

- `/唤醒帮助` ：显示完整帮助信息

## ⚙️ 配置项说明

在 AstrBot 后台插件管理界面进行配置：

| 配置项 | 说明 |
| --- | --- |
| `allowed_users` | 允许使用插件的用户 ID 列表。**必填**：留空将导致所有指令失效（仅限私聊环境生效）。 |
| `enable_multi_device` | 是否启用多设备模式。设为 `true` 时，绑定和开机需指定设备名称；设为 `false` 时为单设备模式。 |
| `wake_timeout` | 唤醒后等待设备上线的超时时间（秒），默认 `90`。适配主板自检慢的设备。 |
| `max_devices` | 单个用户最多绑定的设备数量，默认 `20` (最大99)。 |

## 🛠️ 安装方法

1. 将本插件文件夹放入 AstrBot 的 `data/plugins/` 目录下。
2. 重启 AstrBot，或在后台执行 `reload` 重载插件。
3. 插件会根据 `requirements.txt` 自动安装所需依赖（`ping3`）。若自动安装失败，请手动执行：`pip install ping3`。
4. **重要**：安装后必须进入 AstrBot 插件管理界面，填写 `allowed_users` 白名单，否则无法使用任何功能。
